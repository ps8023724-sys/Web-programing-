1. What this page covers

This page documents the Git work I actually ran: creating a repository, checking its status, staging and committing a file, creating a branch, and merging it back into main. I worked in a GitHub Codespace terminal. The commands and output below are copied from that terminal, and the commit hashes are the ones Git printed.

2. Setting up a repository

I first checked that Git was installed, then created a new repository with main as the starting branch.

$ git --version
git version 2.53.0
$ git init -b main
Initialized empty Git repository in /workspaces/codespaces-blank/.git/

3. My first commit

I created a small index.html file and ran git status before adding it. Git listed the file as untracked, meaning it could see the file but was not recording it yet. git add staged the file for the next commit, and git commit saved it in the history.

$ echo "<h1>Hello Git</h1>" > index.html
$ git status
On branch main

No commits yet

Untracked files:
  (use "git add <file>..." to include in what will be committed)
        Web-programing-/
        index.html

nothing added to commit but untracked files present (use "git add" to track)
$ git add index.html
$ git commit -m "Initial commit: add index.html"
[main (root-commit) a5df21e] Initial commit: add index.html
 1 file changed, 1 insertion(+)
 create mode 100644 index.html
$ git log --oneline
a5df21e (HEAD -> main) Initial commit: add index.html

Result: the file went from untracked to committed as a5df21e. The status output also listed Web-programing-/, which is my separate course-site folder inside the same workspace. I staged only index.html, by name, so the unrelated folder was not included in the commit.

4. Creating a branch and merging it

A branch lets me work on a change away from main. I created feature-style, added a stylesheet and committed it there, then switched back to main. Listing the files showed that style.css was not on main yet, because that file only existed on the branch.

$ git checkout -b feature-style
Switched to a new branch 'feature-style'
$ echo "body { font-family: sans-serif; }" > style.css
$ git add style.css
$ git commit -m "Add basic stylesheet"
[feature-style df1e4f9] Add basic stylesheet
 1 file changed, 1 insertion(+)
 create mode 100644 style.css
$ git checkout main
Switched to branch 'main'
$ ls
Web-programing-  index.html

Then I merged the branch into main. Git reported a fast-forward, which happens when main has no new commits of its own, so Git simply moves it forward to the branch's latest commit.

$ git merge feature-style
Updating a5df21e..df1e4f9
Fast-forward
 style.css | 1 +
 1 file changed, 1 insertion(+)
 create mode 100644 style.css
$ ls
Web-programing-  index.html  style.css
$ git log --oneline --graph --all
* df1e4f9 (HEAD -> main, feature-style) Add basic stylesheet
* a5df21e Initial commit: add index.html

Result: after the merge, style.css appeared on main, and the history shows both commits in a straight line.

6. What I learned

Running the commands myself made the steps easier to understand than reading about them. git status showed me the difference between a file Git can see and a file Git has recorded. The branch exercise showed that files really do disappear and reappear when I switch branches, and that a fast-forward merge only moves the branch pointer. I also learned to stage files by name instead of everything at once, because my workspace contained another project folder that did not belong in that commit.
