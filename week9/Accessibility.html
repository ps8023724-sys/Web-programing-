Week 9 · Web Accessibility

Accessibility Audit

Evaluating and improving the usability of my personal portfolio website for people with different abilities and ways of browsing the web.

01. Introduction

Web accessibility means designing websites so that everyone, including people with visual, hearing, motor, or cognitive disabilities, can use them.

For this assignment, I evaluated my personal portfolio website using Google Lighthouse. I focused on the accessibility category, identified areas that needed improvement, and applied changes to make the website easier to navigate and understand.

03. Accessibility Issues

Structure

Missing Main Landmark

A page should have a clear main content landmark. Without it, screen reader users may have difficulty identifying and jumping directly to the primary content of the page.

Keyboard Navigation

Limited Keyboard Guidance

Users who cannot operate a mouse rely on the keyboard to move through links and controls. A visible focus indicator helps them understand which element is currently selected.

Navigation

No Skip Navigation Link

Keyboard users may have to move through repeated navigation links before reaching the main content. A skip link provides a quicker way to reach it.

04. Improvements Implemented

Fix 1 — Semantic Main Landmark

I placed the primary page content inside the <main> element. This gives assistive technologies a clear landmark for the main content. 

<main id="main-content" tabindex="-1">
    <h1>Welcome to my portfolio</h1>
    <!-- Main page content -->
</main>

Fix 2 — Skip to Main Content

I added a skip link as the first interactive element in the page. It becomes visible when a keyboard user presses the Tab key. 

<a class="skip-link" href="#main-content">
    Skip to main content
</a>

Fix 3 — Visible Keyboard Focus

I added a clear outline around focused links and buttons. This makes keyboard navigation easier to follow. 

a:focus-visible,
button:focus-visible {
    outline: 3px solid #8061AE;
    outline-offset: 4px;
}

Fix 4 — Improved Text Structure

I used meaningful headings, descriptive link text, and semantic HTML elements to make the content easier for assistive technologies to interpret.

Fix 5 — Responsive and Motion-Friendly Design

I made the layout adapt to smaller screens and added a reduced-motion preference so that users who prefer less animation can browse more comfortably.

06. Manual Accessibility Checks

Automated tools cannot identify every accessibility problem. I also checked the following manually:

  • Navigate through the page using only the Tab key.
  • Check that the focus indicator is clearly visible.
  • Test whether the skip link moves to the main content.
  • Check that headings follow a logical order.
  • Make sure text is readable against its background.
  • Check that links have meaningful descriptions.
  • Test the layout on a smaller screen.

07. Conclusion

This audit helped me understand that accessibility is an important part of web development, rather than simply a visual design consideration.

By improving semantic structure, keyboard navigation, focus visibility, and responsive behavior, I made my portfolio more usable for a wider range of people. I also learned that automated testing should be combined with manual checks because accessibility involves real user experiences that a score alone cannot fully measure.
