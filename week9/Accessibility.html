Accessibility Audit of My Portfolio

Week 9 · Shrestha Puja · Student ID 202537250 · Audit run on 4 November 2026

1. What I tested

I audited the home page of my portfolio, ps8023724-sys.github.io/Web-programing-/, using Lighthouse in Chrome DevTools. I ran it with only the Accessibility category selected, once before making any changes and once after.

2. Initial audit: 90 / 100

The page scored 90. Lighthouse reported one failed audit: background and foreground colors do not have a sufficient contrast ratio. It listed three elements: div.student-detail, section.about and strong.

Lighthouse also reported 9 passed audits, 10 items to check manually (unscored), and 53 audits that did not apply to my page.

3. Finding the cause

I looked at the CSS for those elements. The name and student ID in the About section use the class student-detail, which set the text color to #766D87 on a background of #F0ECF8. I calculated the contrast ratio of that pair using the WCAG formula.

ElementText colorBackgroundRatioNeeds
.student-detail (before)#766D87#F0ECF84.19 : 14.5 : 1
.student-detail (after)#5F566F#F0ECF85.93 : 14.5 : 1

The strong element around my name sits inside .student-detail, so it inherited the same low-contrast color. section.about was listed because it supplies the background the text is measured against. All three listed items came from one color.

4. The fix

I darkened the text color of .student-detail to the same color already used for the paragraph beside it, so the design stayed consistent.

/* before */
.student-detail {
    color: #766D87;
}

/* after */
.student-detail {
    color: #5F566F;
}

5. Final audit: 100 / 100

After committing the change and refreshing the live site, I ran Lighthouse again with the same settings. The score rose from 90 to 100 and the contrast audit no longer failed.

6. What the page already did well

Lighthouse showed that the page already passed checks for the lang attribute, the page title, link names, heading order, touch target size, zoom not being disabled, and a main landmark.

7. Manual checks

Lighthouse cannot test everything, so I also checked these by hand.

  • Keyboard navigation (Tab key): I pressed Tab repeatedly and could reach every link on the page. The focus moved in an order that matched the visual layout, from the top of the page down through the week cards.
  • Visible focus outline: The outline around the selected link was clearly visible, so I could always tell which link had focus.
  • Zoom to 200%: At 200% zoom the page still worked and nothing was cut off.

8. What I learned

The audit showed me that a single color choice can trigger several flagged elements. Lighthouse listed three elements, but all of them came from one text color that was too faint on its background. I also learned that a score of 100 only covers what a tool can detect, which is why Lighthouse lists items to check by hand. On future pages I will check text contrast when I choose the colors, instead of leaving it until the end.
