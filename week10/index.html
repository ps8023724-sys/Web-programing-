Part 02 · Monday Practice

Git and Version Control

The following exercises demonstrate repository initialization, staging, commits, branching, merging, and remote repositories.

EXERCISE 01

Create Your First Git Repository

Goal: Initialize a Git repository, create a file, and make the first commit.

I started by checking Git and initializing a repository using the main branch. I created an index.html file, checked its status, staged the file, and committed it. 

git --version

git init -b main

git status

git add index.html

git commit -m "Initial commit: add index.html"

git log --oneline

My actual first commit:

a5df21e Initial commit: add index.html

Result: Git tracked my index.html file after staging it, and I successfully created my first commit.

Local commit completed
EXERCISE 02

Create a Branch and Merge It

Goal: Create a feature branch, make a change, and merge it into the main branch.

I created a new branch called feature-style. On that branch, I created a CSS file and committed the change. Then I switched back to main and merged the feature branch. 

git checkout -b feature-style

git add style.css

git commit -m "Add basic stylesheet"

git checkout main

git merge feature-style

git log --oneline --graph --all

My actual stylesheet commit:

df1e4f9 Add basic stylesheet

Result: The feature-style branch was successfully merged into main using a fast-forward merge. The stylesheet became part of the main branch.

Local branch and merge completed
EXERCISE 03

Push a Repository to GitHub

Goal: Connect a local Git repository to a remote GitHub repository and push its commits.

This exercise demonstrates how a local repository can be connected to GitHub. After creating an empty remote repository, the following commands connect and push it. 

git remote add origin YOUR_GITHUB_REPOSITORY_URL

git remote -v

git push -u origin main

Expected result: The main branch is uploaded to GitHub, and the local branch is configured to track the remote main branch.

Evidence to add: the actual terminal output and the GitHub repository URL for this specific Git exercise. The two commits above are confirmed local commits; this page does not claim that they were pushed to a remote repository.

EXTRA PRACTICE

Creating a Pull Request

Goal: Understand the GitHub collaboration workflow by creating a branch, pushing it, opening a pull request, and merging it.

A pull request allows developers to propose changes from one branch into another. The changes can be reviewed before they are merged into the main branch. 

git checkout -b add-readme

git add README.md

git commit -m "Add project README"

git push -u origin add-readme

After pushing the branch, a pull request can be opened on GitHub. Once reviewed, it can be merged into main.

Evidence to add after completing this exercise: your actual pull request URL, merge confirmation, and updated commit history.

Part 03 · Friday Practice

GitHub Pages and Deployment

These exercises demonstrate how to publish a website and create a better experience for visitors.

EXERCISE 01

Enable GitHub Pages

Goal: Publish a website using GitHub Pages.

I created the webpro-w10 repository and added an index.html homepage. I then configured GitHub Pages to deploy the main branch from the root directory. 

git add index.html

git commit -m "Add homepage"

git push origin main

In the GitHub repository, I opened Settings → Pages, selected Deploy from a branch, chose main and the root directory, and saved the configuration.

Result: My website was published and became accessible through its GitHub Pages URL.

EXERCISE 02

Understand a 404 Error Page

Goal: Understand what happens when a visitor opens a URL that does not exist.

A 404 error occurs when the requested page cannot be found. A default error page may not provide enough information or a helpful way for visitors to return to the website.

My observation:

  • The requested page does not exist.
  • The visitor may not know how to return to the homepage.
  • A custom page can make the experience more friendly.

I used this exercise to understand why websites should provide a clear and useful error page.

Testing evidence to add: a screenshot of the missing-page URL before the custom 404 page was added.

EXERCISE 03

Create a Custom 404 Page

Goal: Create a custom 404.html file and publish it through GitHub Pages.

I added a custom 404.html file to the root of my webpro-w10 repository. The page explains that the requested page is unavailable and provides a link to return to the homepage. 

git add 404.html

git commit -m "Add custom 404 page"

git push origin main

Result: The repository contains a custom 404 page that GitHub Pages can display when a visitor requests a missing page.

Part 04 · Reflection

What I Learned

Through these assignments and exercises, I learned how to organize my web projects, use Git to track changes, and publish websites through GitHub Pages.

I also learned the importance of commits and branches. Instead of treating a project as one final file, Git allows me to record changes step by step and return to earlier versions when necessary.

Working with APIs helped me understand how websites can retrieve and display information from external services. Creating a custom 404 page also showed me that a good website should consider the visitor's experience, even when something goes wrong.

Overall, these activities helped me become more comfortable with the development workflow, from writing code and testing it to managing repositories and deploying a live website.
